1Visão geralOverview

Esta documentação espelha exatamente o comportamento implementado nos arquivos do servidor (api.js e logic.js).

This documentation mirrors the exact behavior implemented in the server files (api.js and logic.js).

Arquitetura: a API HTTP enfileira as operações em uma fila limitada em memória (com persistência opcional no banco para jobs pendentes) e então aguarda o resultado do worker ou devolve uma resposta no formato legado, para compatibilidade. A fila anexa um txId aos payloads para idempotência; se esse txId aparece na resposta HTTP depende das regras de mapeamento por rota implementadas em doEnqueueAndMap.

Key architecture: the HTTP API enqueues write operations into a bounded in-memory queue (with optional DB persistence for pending jobs) and then either waits for the queue worker result or returns a legacy-shaped response for backward compatibility. The queue attaches a txId to payloads for idempotency; whether that txId appears in the HTTP response depends on per-route mapping rules implemented in doEnqueueAndMap.

Valores: as Coins usam 8 casas decimais (1 coin = 100.000.000 sats). Os endpoints de cartão truncam o valor para 8 casas (Math.floor(amount * 1e8) / 1e8).

Amounts: Coins use 8 decimal places (1 coin = 100,000,000 sats). Card endpoints truncate the amount to 8 decimals (Math.floor(amount * 1e8) / 1e8).

3Fila e idempotênciaQueue & idempotency

  • O servidor usa queue.enqueueAndWait(payload). Antes de enfileirar, doEnqueueAndMap garante payload.args.ip e anexa payload.txId = UUID aleatório se não informado.
  • Se a fila recusar com ENQUEUE_REJECTED, o wrapper tenta um cache em memória e um job pendente no banco. Se isso também falhar, a API responde 429 / { error: "QUEUE_FULL" }. O worker de cache depois despeja os itens pendentes na fila.
  • Rotas que passam por doEnqueueAndMap também aplicam limite por IP (token bucket: RATE_LIMIT_PER_IP/s, rajada RATE_LIMIT_BURST, padrão 10) → 429 RATE_LIMIT_EXCEEDED.
  • Mapeamento legado por rota:
    • legacyReturn: 'transfer' → resposta sempre { success: true } (oculta o txId).
    • legacyReturn: 'transfer_card' → { success: true, txId?, date? } se o resultado do worker tiver txId; caso contrário { success: true }.
    • Padrão (sem legacyReturn) → devolve o resultado do worker como está.
  • The server uses queue.enqueueAndWait(payload). Before enqueueing, doEnqueueAndMap ensures payload.args.ip is set and attaches payload.txId = a random UUID if not provided.
  • If the queue refuses with ENQUEUE_REJECTED the wrapper attempts an in-memory cache and a DB pending job. If that also fails, the API returns 429 / { error: "QUEUE_FULL" }. The cache worker later flushes pending items into the queue.
  • Routes going through doEnqueueAndMap also apply a per-IP rate limit (token bucket: RATE_LIMIT_PER_IP/s, burst RATE_LIMIT_BURST, default 10) → 429 RATE_LIMIT_EXCEEDED.
  • Per-route legacy mapping:
    • legacyReturn: 'transfer' → response is always { success: true } (hides txId).
    • legacyReturn: 'transfer_card' → response is { success: true, txId?, date? } if the worker result contains a txId, otherwise { success: true }.
    • Default (no legacyReturn) → returns the worker result as-is.

7txId: geração e quando aparece nas respostastxId: generation & when responses include it

  • Todo payload enfileirado recebe um payload.txId (UUID) para idempotência; o servidor só define se o cliente não enviar um.
  • Se a resposta HTTP inclui o txId depende do mapeamento da rota:
    • legacyReturn: 'transfer' → sempre { success: true } (txId oculto).
    • legacyReturn: 'transfer_card' → { success: true, txId?, date? } se o resultado tiver txId; senão { success: true }.
    • Padrão → resultado do worker como está, que pode incluir txId se a função de lógica o retornar.
  • Para sempre receber o txId, envie-o no corpo da requisição ou altere o mapeamento em doEnqueueAndMap.
  • Com o txId, o comprovante público fica em /tx.html?id=<txId>.
  • Every enqueued payload receives a payload.txId (UUID) for idempotency; the server only sets it if the client didn't provide one.
  • Whether the HTTP response includes the txId depends on the route mapping:
